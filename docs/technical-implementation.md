# 文件中转站（File Hub）技术实现方案

> **阶段范围：** Windows 本地文件发现、标记和文件库管理。  
> **不在第一阶段：** 内部网页外发集成。网页集成留待后续阶段。

## 1. 产品目标与流程

文件中转站监控受支持的浏览器和用户自行配置的客户端程序，发现新文件并在文件写入完成后提示用户填写业务标记。第一阶段的完整流程：

1. 在设置中配置监听程序、监听目录、提醒和过滤规则。
2. 发现候选文件并判断文件是否已写入完成。
3. 将有效文件加入“待标记”队列，按设置弹出提醒。
4. 用户填写项目、文件版本号、预计发送对象、预计发送时间、标签和备注。
5. 用户选择“保存标记”“保存并入库”或“忽略文件”。
6. 在文件库中查看和编辑已入库文件，查询来源、版本和操作记录。

第一阶段只记录预计发送计划，不执行实际外发，也不尝试阻止用户绕过中转站发送文件。

## 2. 技术选型

| 模块 | 技术 | 职责 |
|---|---|---|
| 桌面客户端 | Electron + React + TypeScript | 页面、窗口、交互和桌面通知 |
| 本机监控代理 | C# / .NET 10 LTS | Windows 文件监听、候选事件处理、完成判断和 SQLite 写入 |
| 浏览器监听 | Chrome / Edge Manifest V3 扩展 | 获取浏览器下载状态、路径和下载元数据 |
| 扩展通信 | Native Messaging Host | 将浏览器下载事件安全转发给本机代理 |
| 目录监听 | ReadDirectoryChangesW / .NET FileSystemWatcher | 监听用户配置的目录和子目录 |
| 进程 I/O 辅助发现 | Windows ETW 文件 I/O 事件（按应用验证） | 帮助发现指定客户端在不同目录中的文件写入 |
| 本地数据库 | SQLite | 配置、文件台账、版本、标记和操作记录 |
| 内容指纹 | SHA-256 | 内容去重与版本内容校验 |
| 打包 | electron-builder / NSIS + 自包含 .NET Agent | 安装和升级桌面端、代理及 Native Messaging Host |

推荐部署三个本机组件：`FileHub.exe`（Electron UI）、`FileHub.Agent.exe`（监控代理）、`FileHub.NativeHost.exe`（浏览器消息桥接）。它们由同一个安装包安装，但职责分离。

## 3. 文件监听策略

### 3.1 浏览器：下载事件为主

为 Edge、Chrome 提供扩展，使用 Downloads API 监听下载状态。下载完成后向 Native Messaging Host 发送标准事件，包含浏览器类型、下载项 ID、文件名、目标路径、下载状态、时间、大小，以及浏览器允许且用户同意保存的元数据。

浏览器会报告实际目标路径，因此无需假定所有浏览器使用同一目录。扩展未安装或未连接时，设置页应明确显示“浏览器监控不可用”。

### 3.2 普通客户端：用户配置程序与目录

设置页必须提供“监听程序”区域，用户可通过文件选择器添加任意 EXE，并维护名称、完整路径、监控方式、启用状态和可选的辅助进程规则。

支持的监控模式：

- **目录监听：** 监听用户指定的目录；适合下载位置已知的客户端。
- **进程 I/O 辅助监控：** 评估 ETW 文件 I/O 事件，发现目标进程相关的文件创建、写入和重命名，辅助发现未知目录中的候选文件。
- **组合模式：** 进程 I/O 候选发现 + 目录监听 + 文件完成判断；推荐作为非浏览器客户端的默认尝试方式。

普通客户端可能使用辅助进程、缓存目录或系统服务写入文件。只配置主 EXE 不能保证捕获其全部下载。ETW 事件只表示文件 I/O，不等于“下载已完成”；应按客户端实测，无法可靠识别的情况提示用户补充目录或显示“部分支持”。

### 3.3 目录规则

每条目录规则包含路径、关联程序、是否递归、是否启用和排除规则。程序启动、代理重启、监听缓冲区溢出或监控恢复时，对已配置目录进行补偿扫描，减少漏报。目录监听用于补充监控，而不是要求所有应用统一使用 Downloads 目录。

## 4. 文件完成、过滤与去重

标准流程：

1. 接收浏览器完成事件或普通客户端候选事件。
2. 规范化路径，检查文件是否存在且可访问。
3. 过滤临时文件、缓存目录和用户排除规则。
4. 对普通客户端文件，观察文件大小与最后修改时间是否稳定，并处理文件占用和重试。
5. 关联临时文件到最终文件的重命名，避免将 `.crdownload`、`.part`、`.tmp` 等误认为最终文件。
6. 异步计算 SHA-256 并创建文件发现记录。
7. 将有效文件放入待标记队列，按用户设置显示弹窗或系统通知。

文件大小稳定只是启发式判断，不是绝对证明。大文件、网络盘和同步目录应支持更长的等待窗口与重试。哈希计算不得阻塞 UI 或文件监听线程。

去重规则：
- 初步去重使用规范化路径、大小、修改时间和短时间窗口。
- 稳定后用 SHA-256 判断内容是否相同。
- 相同内容但不同路径仍保留独立发现事件，可提示复用内容。
- 同一路径内容变化时重新计算指纹，提示用户确认是否建立新版本。
- 文件名相同不能作为内容相同的依据。

## 5. 页面与交互闭环

第一阶段只保留五个页面：**首页概览、下载监听、待标记、文件库、设置**。设计稿索引见 [设计稿目录](./design/README.md)。

### 5.1 首页概览

显示今日发现、待标记、已入库三个数字，以及最近文件和待处理提醒。点击数字或提醒应跳转到对应列表并应用相应筛选；数字必须来自数据库真实状态。

### 5.2 下载监听

显示文件名、来源应用、保存位置、发现时间、当前状态和操作。筛选“全部 / 浏览器 / 客户端”、来源应用筛选和刷新必须实际生效。

- “立即标记”：打开待标记页并选中对应文件。
- “忽略”：确认后状态改为已忽略，保留操作记录。
- “查看”：打开对应文件详情或文件库记录。

### 5.3 待标记

左侧为待处理文件队列，右侧为选中文件摘要与表单。系统自动填写文件名、来源、路径、大小和发现时间；用户填写项目、业务版本号、预计发送对象（支持多个）、预计发送时间、标签和备注。

按钮语义：
- **保存标记：** 保存业务信息，状态转为“已标记 / 待入库”。
- **保存并入库：** 保存标记，将文件复制到受控仓库；只有复制成功后才能标记为“已入库”。
- **忽略文件：** 确认后进入“已忽略”，不纳入文件库。
- **稍后处理：** 只关闭编辑视图，文件仍留在待标记队列。

校验或保存失败时保留用户输入并展示错误，不得提前更新状态。

### 5.4 文件库

仅显示已完成标记并成功入库的文件。支持搜索、项目/标签筛选、查看详情、编辑标记和打开文件位置。业务版本号与 SHA-256 含义不同：版本号由用户或业务规则维护，SHA-256 用于校验文件内容。

若原始文件被移动或删除，应显示不可用状态；若文件内容发生变化，应提示用户确认并建立新版本，而不是静默覆盖历史内容。

### 5.5 设置

设置页必须包含以下三个区域。

**监听程序**
- “添加程序”打开 Windows 文件选择器，允许用户选择 `.exe`。
- 展示程序名称、EXE 路径、监控方式、启用开关和运行状态。
- 监控方式包括浏览器下载事件、目录监听、进程 I/O 辅助监控和组合模式。
- 支持编辑、启用/停用、删除；更改后通知 Agent 动态重载。
- 浏览器模式显示扩展连接状态；不支持的模式应明确显示原因。

**监听目录**
- “添加目录”打开目录选择器。
- 配置路径、关联程序、递归监听、启用状态和排除规则。
- 支持编辑、停用、删除。删除规则只停止未来监听，不删除已记录的文件或原始文件。

**提醒与过滤**
- 发现新文件时弹窗提醒。
- 忽略临时文件（如 `.tmp`、`.cache`）。
- 仅提醒常见文档类型（可选）。
- 可选配置最小文件大小、排除目录和扩展名。

设置应持久化，且 UI 应显示 Agent 是否已应用。普通目录监听通常不需要管理员权限；ETW 的权限要求单独评估，不应默认以管理员身份运行整个应用。

## 6. 状态机

| 状态 | 含义 | 允许操作 |
|---|---|---|
| `DETECTED` | 候选文件，等待完成检查 | 稳定后转待标记；失败时重试或报错 |
| `PENDING_TAG` | 已确认可访问，等待标记 | 保存标记、保存并入库、忽略 |
| `TAGGED_PENDING_ARCHIVE` | 已保存标记，尚未入库 | 编辑标记、保存并入库、忽略 |
| `IN_LIBRARY` | 标记和入库成功 | 查看、编辑标记、打开位置、确认新版本 |
| `IGNORED` | 用户明确忽略 | 查看记录、手动恢复到待标记 |
| `ERROR` | 检测或存储操作失败 | 查看原因、重试、忽略 |

所有状态迁移必须由成功操作触发，并写入操作记录。失败操作不得让界面显示成功。

## 7. 本地数据模型

建议至少包含：

- `MonitoredProgram`：程序 ID、名称、EXE 路径、进程匹配规则、监控模式、启用状态。
- `WatchDirectory`：目录 ID、路径、关联程序、递归开关、排除规则、启用状态。
- `FileAsset`：逻辑文件 ID、显示名称、项目、分类、当前状态。
- `FileVersion`：版本 ID、逻辑文件 ID、业务版本号、原始路径、受控仓库路径、大小、SHA-256、来源、发现时间。
- `DetectionEvent`：事件来源、进程 ID、路径、发现时间、检测状态和诊断信息。
- `FileAnnotation`：版本 ID、项目、预计发送对象、预计发送时间、标签、备注。
- `OperationLog`：操作类型、文件/版本 ID、时间、结果和错误详情。

预计发送对象和时间属于计划信息，不代表文件已发送。

## 8. 安全与可靠性

- Electron Renderer 禁用 Node.js 集成，启用 `contextIsolation` 与 sandbox；只通过白名单 IPC 调用本机能力。
- Native Messaging Host 只接受登记的扩展来源与结构合法的消息，不提供任意命令执行能力。
- 本地数据库和仓库目录放在用户应用数据目录，并使用当前用户 ACL。
- UI 与监听处理解耦；Agent 崩溃后可重启，启动时扫描配置目录恢复漏掉的事件。
- 高频下载可合并弹窗通知，但每个文件仍必须有独立台账。
- 日志避免默认保存完整 URL、文件内容或不必要的敏感信息。

## 9. 实施阶段与验收

### 阶段一：管理骨架
Electron 页面、SQLite、状态机、监听程序配置、监听目录配置、待标记和文件库流程。

### 阶段二：浏览器监听
Edge/Chrome 扩展、Native Messaging Host、下载完成事件、路径和异常状态处理。

### 阶段三：普通客户端监听
目录监听、启动扫描、周期补偿扫描、ETW 文件 I/O 原型验证，并针对用户添加的客户端进行兼容性测试。

### 阶段四：闭环与安装
文件完成判断、过滤、去重、SHA-256、通知、安装升级和恢复测试，形成明确的客户端支持矩阵。

验收标准：
- 用户能添加、编辑、启用、停用、删除监控程序。
- 用户能添加多个目录并配置递归监听。
- Edge/Chrome 下载到不同目标目录的文件可被发现。
- 配置目录的文件变化可被发现；重启和事件遗漏可通过扫描补偿。
- 文件未完成写入时不进入正式待标记状态，临时文件按规则过滤。
- 保存标记、保存并入库、忽略三条流程状态正确。
- 只有受控仓库操作成功的文件才显示已入库。
- 设置和文件台账在重启后保留。
- 对普通客户端展示监控方式与限制，不把 I/O 事件误报为确定的下载完成事件。

## 10. 后续网页外发集成（不属于第一阶段）

后续可通过 Electron `WebContentsView` 嵌入内部外发网页，复用网页已有的收件人选择、审批和发送流程。网页点击“从文件中转站选择”后，由受控 IPC 选择文件版本，本机代理上传到内部后端，网页获得附件 ID、版本 ID 和 SHA-256 后继续原有流程。

实际发送对象、时间和结果必须以网页后端记录为准，再由 EXE 通过认证 API 同步。此阶段需另行设计登录认证、上传权限、文件大小限制、失败重试和审计接口。
