# File Hub 技术实现方案

> 当前开发版本：**0.2.0（尚未发布）**。基线版 [v0.1.0](https://github.com/spring-it/file-hub/releases/tag/v0.1.0) 不包含本分支的合并工作区与 ETW Agent。

## 1. 范围与页面

第一阶段负责 Windows 本地文件发现、业务标记和受控文件库。内部网页外发集成不在本阶段范围内；“预计发送给谁、何时发送”仅为业务计划信息，不代表文件已发送。

客户端只保留四个主要页面：

1. **首页概览**：今日发现、待标记、已入库、最近文件和待处理提醒。
2. **下载监听与标记**：左侧下载记录和筛选，右侧当前文件标记表单。发现、选中、标记、稍后处理、忽略、保存和入库在同一工作区完成。
3. **文件库**：仅显示成功复制入库的文件，可查看详情、编辑标记、打开文件位置。
4. **设置**：监听程序 EXE、监听目录、递归与启用开关、提醒和文件类型过滤。

保存标记只保存业务信息；只有受控副本成功复制并完成 SHA-256 校验后，状态才转为“已入库”。

## 2. 运行架构

| 组件 | 实现 | 职责 |
|---|---|---|
| 桌面 UI | Electron + React + TypeScript | 四个页面、设置、托盘和操作反馈 |
| 目录监听 | Electron 主进程 + Node.js `fs.watch` | 监听用户配置目录，启动扫描和周期补偿扫描 |
| 浏览器监听 | Edge/Chrome Manifest V3 扩展 | 通过 Downloads API 获取完成事件和目标路径 |
| 浏览器桥接 | `FileHub.exe` Native Messaging 模式 | 接收浏览器事件，执行去重并写入本地台账 |
| 进程级监听 | .NET 10 + Microsoft.Diagnostics.Tracing.TraceEvent | 可选 ETW 文件 I/O Agent，监控设置中指定的 EXE 及子进程 |
| 进程事件管道 | Windows 本地命名管道 | Agent 向 Electron 发送文件路径、来源程序和诊断事件 |
| 本地数据库 | Node.js `node:sqlite` | 程序/目录设置、文件台账、标记和操作日志 |
| 内容校验 | 流式 SHA-256 | 内容指纹、入库前后校验和重复发现判断 |
| Windows 提醒 | Electron 原生 `Notification` | Windows 通知区域提示；点击通知打开对应文件的标记工作区 |
| 安装包 | electron-builder + NSIS | 安装桌面端、浏览器 Native Messaging Host 与自包含 ETW Agent |

Electron Renderer 禁用 Node.js 集成，启用 `contextIsolation` 和 sandbox；本机文件操作只经白名单 IPC。ETW Agent 只在用户明确选择“进程 I/O + 目录”时启动，并通过 UAC 请求管理员权限；目录监听与浏览器模式不需要因此提升整个桌面程序权限。

## 3. 监听方式

### 3.1 浏览器下载事件

Edge/Chrome 扩展在下载完成时发送浏览器类型、下载项 ID、文件路径、时间和大小。浏览器目标路径来自下载 API，不假设所有浏览器使用同一目录。扩展需手动加载或通过企业策略部署，并在设置中启用对应浏览器 EXE。

如果目录监听先发现了同一文件，浏览器完成事件会把来源记录细化为浏览器；去重后不会重复创建台账。

### 3.2 目录监听

用户可以添加多个目录，关联某个客户端或作为通用目录，选择递归监听和启用状态。Windows 下使用 Node.js `fs.watch`，同时进行启动扫描与周期补偿扫描。目录模式适用于保存位置已知的客户端。

### 3.3 ETW 进程 I/O + 目录

设置中的组合模式仅允许非浏览器 EXE。启用或重新启动进程监听时，Electron 在 Windows 上创建随机命名的本地管道，并通过 PowerShell 的 `Start-Process -Verb RunAs` 请求启动自包含 ETW Agent，因此可能再次出现 UAC 提示。

Agent：
- 订阅 Kernel Process 与 File I/O 事件，按完整 EXE 路径匹配设置中的目标程序。
- 关联已配置进程启动的子进程，以覆盖常见辅助下载进程。
- 上报文件创建、写入和重命名候选；不把 I/O 事件直接当作下载完成。
- 使用有界事件队列和路径去抖。队列溢出时发送警告，避免无界内存增长。
- 如果管理员权限被拒绝、ETW 会话无法启动或本地管道断开，会报告错误，目录监听仍可继续。

ETW 只证明某个进程执行了文件 I/O，不保证它是“下载”。保护目录、服务进程、网络盘、重命名、客户端升级和长时间运行均需目标电脑实测。浏览器应优先使用下载扩展，不建议对 Chrome/Edge 选择 ETW 组合模式。

## 4. 文件候选处理与性能

目录与 ETW 候选进入同一稳定性检查流程：

1. 规范化路径并过滤临时文件和排除路径。
2. 观察文件大小与最后修改时间，确认短时间稳定；文件持续变化时重试。
3. 使用流式 SHA-256，不把整个文件读入内存。
4. 以规范化路径、大小和修改时间进行数据库去重；浏览器/ETW 来源事件可以细化既有记录。
5. 创建待标记台账；所有来源共用标记、忽略、入库和文件库流程。

当前保护阈值：
- 每次补偿扫描最多处理 20,000 个文件项、最多排队 250 个候选，递归深度最多 8。
- 启动时扫描最近 24 小时文件且不为历史文件弹通知；每 5 分钟扫描最近 10 分钟变化项。
- SHA-256 并发上限为 4，扫描候选分批处理。
- 文件系统事件通过短时去抖合并；Windows 通知在 450ms 窗口内合并下载洪峰，通知队列最多缓存 1,000 条并在超出时汇总数量。
- SQLite 使用 WAL、正常同步模式、busy timeout 和路径/去重索引。

这些是默认保护参数，不是所有设备上的性能保证。超大文件、网络盘、同步文件夹和高频辅助进程仍需在真实环境测量。

## 5. 状态与业务闭环

| 状态 | 含义 | 操作 |
|---|---|---|
| `PENDING_TAG` | 文件已发现，待补充标记 | 保存标记、保存并入库、忽略 |
| `TAGGED_PENDING_ARCHIVE` | 标记已保存，待入库 | 编辑标记、保存并入库、忽略 |
| `IN_LIBRARY` | 标记与受控副本均成功 | 查看、编辑标记、打开位置 |
| `IGNORED` | 用户明确忽略 | 查看、恢复 |
| `ERROR` | 检测或存储操作失败 | 查看原因并重试/忽略 |

“稍后处理”只跳转到下一个待处理项，不改变当前文件状态。保存失败时保留输入并显示错误，不得提前更新状态。忽略与恢复均保留台账记录。

## 6. Windows 通知

Electron 在 Windows 启动前设置 AppUserModelID `com.springit.filehub`，并通过原生 `Notification` 发送通知。短时间多个文件会合并为数量提示，点击通知后聚焦或启动 File Hub 并打开一个对应文件的标记表单；其余文件仍保留在下载记录列表。Windows 系统设置若关闭该应用的通知，应用无法绕过系统策略强制显示。

## 7. 构建与验证

Windows CI 执行：
1. Node.js 22 与 .NET 10 SDK 安装。
2. Node 测试、运行时脚本语法检查、TypeScript 检查和 Vite 构建。
3. 自包含 ETW Agent 发布与路径匹配自测。
4. NSIS 安装包构建。
5. 在 CI 权限允许时启动真实 ETW 内核会话，验证配置进程的文件写入事件能通过命名管道返回；如果托管 Runner 没有权限，会在日志中明确跳过该集成测试。
6. 安装包存在性检查与构建产物上传。

CI 成功不能替代目标 Windows 桌面上的 UAC、右下角通知、浏览器扩展、托盘、卸载清理、网络盘和长时间运行验收。发布门槛仍包含这些实机检查。

## 8. 已知限制与后续工作

- 当前分支的 v0.2.0 尚未发布；已发布的 v0.1.0 不包含本分支更改。
- 普通客户端 ETW 的实际支持程度取决于权限、进程树、客户端实现与系统环境；需要逐个客户端建立支持矩阵。
- 内部网页外发集成仍待后续阶段，通过受控 API 或 Electron WebContentsView 复用网页现有的收件人选择、审批、上传和发送流程。
- 实际发送对象、时间和结果必须以内部网页后端记录为准；本地“预计发送”字段不能被解释为发送成功。
